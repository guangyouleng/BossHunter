# 招聘端浏览器操作与故障诊断

适用版本：2.4.2。只描述招聘端；不改变现有节流、消息监测和人工授权范围。

## 岗位切换

切换到另一个岗位只点击一次目标选项，然后核对：

1. 推荐 iframe 的选中岗位 ID 与目标一致。
2. 候选列表在点击目标岗位后发生了内容更新；点击前的后台刷新、仅展开下拉框、改变岗位标签或鼠标悬停不算列表更新。
3. 当前有已加载候选卡，或出现明确的空列表提示；加载状态已经结束。
4. 上述状态连续稳定至少 500 ms，并重新核对登录会话。

已经在目标岗位时不重复点击，但仍检查列表就绪。默认最多等待 15 秒；超时停止，不能继续使用旧岗位列表。读取候选人前后再次核对岗位 ID。界面状态检查只读取本地 DOM，不增加 BOSS HTTP 轮询。

临时 MutationObserver 只存放在浏览器句柄中，结束时释放，不向 window 或 DOM 写入标记。

下拉菜单已经展开时不重复点击开关。已进入招呼点击步骤后停止任务，若结果尚未核实，仍保存待核实状态并阻止继续外发，不能当作未发送取消。

## CloakBrowser 交互范围

只在 `browser.recruiting_browser_kind: cloakbrowser` 且 `browser.cloakbrowser_humanize: true`（默认）时启用官方 `cloakbrowser.human` 层。源码需安装 `.[recruiting,cloakbrowser]` 可选依赖，Windows 打包会带上 Python 交互层及 Playwright 驱动；浏览器本体仍由用户提供。设置在进程创建适配器时读取，修改后需重启。

- 打招呼：定位唯一候选人和按钮，移动后重新核实岗位、账号、任务与文案；临时输入事件保护在点击期间检查岗位/候选人身份，结束后释放。按钮必须明确变成“继续沟通”才能记为成功。点击异常或无法确认结果不重试，保留待核实。
- 岗位选择：真实鼠标点击下拉框/选项；仅从目标选项实际点击那一刻开始记录候选列表变化，保留原列表就绪与稳定核验。临时监听器随操作释放。
- 联系人：根据已知联系人元素的可滚动祖先定位区域，核实可见位置后移入并分段滚轮加载；不会点选候选人。未知布局、遮挡或区域移动时停止。列表仍按原分页节流加载，覆盖范围继续标为当前页面可加载联系人。

- 普通回复：逐字输入并短暂停顿，不模拟错字、回删或清空编辑器。每个字符前后核实会话、消息、焦点、光标和当前内容；换行用文本插入，避免回车快捷键提前发送。期间变化就停止并保留现有内容。完成后重新核验并拟人点击一次发送，原消息结果确认流程不变；进入发送点击后的取消仍按待核实处理。

简历操作、Chrome 模式、WS/HTTP 监测不使用此交互层。只连接绑定标签页，不激活或新建页面；缺少依赖不会退回另一种点击方式。本地模拟验证使用全新隔离资料和离线页面，不验证 BOSS 风控；桌面这份浏览器的离线验证范围见下文。浏览器交互模块与移除说明见 [浏览器后端](BROWSER_BACKENDS.md)。

## 页面分类

| 分类 | 行为 |
| --- | --- |
| 登录失效、安全验证、已知平台风险提醒、403/429 | 统一暂停，保留页面供人工处理；不解验证码、不屏蔽安全脚本、不强制导航回业务页 |
| 付费墙/权益提示 | 停止当前操作，提示人工核对，不自动购买 |
| 普通未处理弹窗 | 停止当前操作，不自动关闭 |
| iframe/选择器缺失、岗位不一致、列表未就绪 | 停止相应操作，保存结构化诊断 |
| 浏览器正忙 | 不执行本次冲突操作；人工稍后重试，自动招呼任务停止并记录原因 |

只识别已知路径和可见弹窗；候选人聊天正文不参与风险文案判定。无法访问的跨域 iframe 不通过修改浏览器安全设置读取。求简历的受控确认步骤仅允许匹配的普通确认框，安全/付费提示仍阻止后续动作。

## 跨进程协调

Web、worker 和主动招呼线程使用招聘数据库内同一个 `browser-dom` 租约。岗位切换与列表读取、发送账号核实与提交/结果核对在各自短操作区间内协调；同线程嵌套可重入，不同线程/进程不可重入。

HTTP 节流等待、模型生成和联系人分页等待不持有 DOM 租约。联系人滚动每步分别取得租约。WS 的被动监听与本地连接状态查询不受写操作互斥影响。Windows 使用只读进程等待状态检查，不调用 `os.kill(pid, 0)`（该调用在 Windows 的行为见 [Python 文档](https://docs.python.org/3.12/library/os.html#os.kill)）。进程退出后的失效租约在下一次操作时回收；前端显示上次操作中断。没有新增自动切换会话、自动重发或外发失败兜底。

## 配置与诊断位置

- `src/bosshunter/data/recruiting_dom.json`：集中 CSS 选择器、已知验证/登录路径。随 wheel 和 Windows 安装包携带。
- `src/bosshunter/recruiting/dom.py`：只读/动作 DOM 脚本。选择器替换在注入用户文本之前完成。
- `src/bosshunter/recruiting/page_state.py`：页面分类。
- `src/bosshunter/recruiting/operations.py`：跨进程互斥和错误归档。
- 前端“运行记录 → 浏览器故障诊断”：最近 20 条，可展开查看阶段、分类、页面路径及结构状态；运行中的操作也显示在页面状态提示中。

诊断不会主动截图、下载页面或请求平台。不保存 Cookie、凭据、聊天正文、简历、候选人姓名和任意异常原文；URL 去掉凭据/参数/片段，简历/推荐框架动态路径脱敏。后台错误经同一数据库展示，服务重启后记录保留。

本次没有提供“防封号保证”。自动化浏览器/CDP、BOSS 当前页面结构及完整业务流程仍需真机验收。
